# Lab 4 Notes

## Question 1
`--global` sets the configuration for the current user across all Git repositories on the system (stored in `~/.gitconfig`). If left out, the setting would only apply locally to the current repository (`.git/config`).

## Question 2
The hidden directory `.git` appeared in `ls -a`. Inside it are Git's internal data structures, configuration files, hooks, refs, and the object database (`HEAD`, `config`, `objects/`, `refs/`, etc.).

## Question 3
Git offered to track about 2 items (`.vscode/` and `sample.py`). Items like `.vscode/` or editor-specific configuration folders are generated by tools rather than written manually.

## Question 4
Any files or directories matching the patterns in `.gitignore` (such as `.venv/` or compiled python caches) are ignored and no longer shown under untracked files in `git status`.

## Question 5
`.gitignore` must be committed to the repository rather than ignored. Committing it ensures that every collaborator who clones or works on the repository shares the same rules for ignoring unwanted files.

## Question 6
`README.md` moved from "Untracked files" to "Changes to be committed". In the three-places model, it moved from the Working Tree into the Staging Area (Index).

## Question 7
Git printed the commit summary with the branch name, short commit hash, commit message, and file change statistics showing files changed and insertions created.

## Question 8
The first seven characters are called the short commit hash (or SHA-1 hash). They serve as a unique identifier for that specific snapshot/commit in Git's history.

## Question 9
The four steps of the Git loop are: 1) Edit/modify files in the working directory, 2) Check the state with `git status`, 3) Stage changes using `git add`, and 4) Commit the snapshot with `git commit -m "<message>"`.

## Question 10
`README.md` is standard convention across software development and Git platforms. GitHub automatically renders it directly on the repository's main page as the entry point and primary overview of the project.

## Question 11
`gh auth login` authenticates via OAuth and sets up Git's credential helper. It securely stores an access token so you do not need to enter your personal password every time you push.

## Question 12
`README.md` is displayed on the front page. GitHub is built to automatically parse and render top-level markdown README files into formatted HTML for visitors.

## Question 13
No, running `git push` did not change the local commit history at all. It simply uploaded the commits and updated the remote tracking branch `origin/main` to match `main`.

## Question 14
A private repository exists securely backed up on GitHub's cloud servers, accessible to you and authorized collaborators (like your TAs). A repository that doesn't exist on GitHub only lives locally on your computer, with no cloud backup, no remote version history, and no way for collaborators to review it.
